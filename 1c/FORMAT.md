# Формат выгрузки проводок «findir-postings»

Файл, который внешняя обработка выгружает из 1С, а FINDIR принимает.
Описание одно на обе стороны: меняете формат — правьте здесь и в обоих кодах.

## Общее

- Кодировка **UTF-8 без BOM**. BOM ломает разбор JSON: он попадает в начало
  строки, и `json_decode` возвращает `null` без объяснений.
- Даты — ISO 8601 без часового пояса: `2026-09-05T00:00:00` или `2026-09-05`.
  1С хранит время локальным, и метка пояса означала бы точность, которой нет.
- Суммы и количества — **числа**, не строки. Разделитель дробной части — точка.
- Пустое значение — **отсутствующий ключ** или `null`, но не пустая строка:
  «поле не заполнено» и «поле равно пустой строке» это разные вещи. Приёмник
  оба варианта читает одинаково.

  Наша обработка пустые ключи **опускает**: `ЗаписатьJSON` в 1С не умеет
  записывать ни `Неопределено`, ни `Null`, обозначить пустоту значением там
  нечем. Файлы из других источников могут писать `null` — это допустимо.

## Структура

```json
{
  "format": "findir-postings",
  "version": 1,
  "source": {
    "app": "1С:Бухгалтерия",
    "config": "Бухгалтерия предприятия, редакция 3.0 (3.0.157.28)",
    "processing": "1.0"
  },
  "organization": { "name": "ООО Ромашка", "inn": "7701234567", "kpp": "770101001" },
  "period": { "from": "2026-09-01", "to": "2026-09-30" },
  "exported_at": "2026-09-07T12:30:00",
  "entries": [
    {
      "id": "9f3ca41e-6b2d-11ee-9e2a-005056bd1234:3",
      "date": "2026-09-05T14:20:00",
      "document": {
        "type": "Списание с расчетного счета",
        "number": "БП-000123",
        "date": "2026-09-05"
      },
      "content": "Оплата поставщику по счёту 451",
      "amount": 120000.00,
      "debit": {
        "account": "60.01",
        "quantity": null,
        "subconto": [
          { "kind": "Контрагенты", "name": "ООО Ромашка", "inn": "7701234567" },
          { "kind": "ДоговорыКонтрагентов", "name": "Основной договор" }
        ]
      },
      "credit": {
        "account": "51",
        "quantity": null,
        "subconto": [
          { "kind": "БанковскиеСчета", "name": "Расчётный счёт в Т-Банке" }
        ]
      }
    }
  ]
}
```

## Поля

### Корень

| Поле | Обяз. | Смысл |
|---|---|---|
| `format` | да | Всегда `findir-postings`. По нему отличаем свой файл от чужого |
| `version` | да | Версия формата, сейчас `1` |
| `source` | нет | Откуда выгружено: приложение, конфигурация, версия обработки |
| `organization` | нет | Организация 1С: название, ИНН, КПП |
| `period` | да | Период выгрузки, `from` и `to` включительно |
| `exported_at` | нет | Когда сформирован файл |
| `entries` | да | Массив проводок. Может быть пустым — это не ошибка |

### Проводка (`entries[]`)

| Поле | Обяз. | Смысл |
|---|---|---|
| `id` | да | `GUID регистратора` + `:` + номер строки движения |
| `date` | да | Дата и время проводки |
| `document` | нет | Документ-регистратор: вид, номер, дата |
| `content` | нет | Содержание проводки из 1С |
| `amount` | да | Сумма проводки. Может быть отрицательной — это сторно |
| `debit` | да | Дебетовая сторона |
| `credit` | да | Кредитовая сторона |

### Сторона (`debit` / `credit`)

| Поле | Обяз. | Смысл |
|---|---|---|
| `account` | да | Код счёта 1С: `51`, `60.01`, `90.01.1` |
| `quantity` | нет | Количество по этой стороне, если счёт количественный |
| `subconto` | нет | Массив субконто, до трёх, в порядке слотов плана счетов |

### Субконто (`subconto[]`)

| Поле | Обяз. | Смысл |
|---|---|---|
| `kind` | да | Имя вида субконто в метаданных: `Контрагенты`, `Номенклатура`, `СтатьиЗатрат` |
| `name` | да | Представление элемента — по нему идёт сопоставление со справочником FINDIR |
| `inn` | нет | ИНН, если субконто — контрагент. Надёжнее имени при сопоставлении |
| `code` | нет | Код элемента в справочнике 1С |

Порядок в массиве значим: первый элемент — субконто 1 плана счетов, второй —
второе и так далее. Незаполненные слоты **пропускаются**, а не отдаются как
`null`: пустое субконто нечего сопоставлять, а порядок восстанавливается по
`kind`.

## Почему `id` устроен так

`GUID регистратора : номер строки` устойчив между выгрузками: перевыгрузили тот
же месяц — идентификаторы те же, и повторная загрузка не создаст дублей.
Ни номер документа, ни дата такой устойчивости не дают — номер можно
перенумеровать, дату сдвинуть.

Хранится он на стороне FINDIR в `integration_links.external_id` (191 символ), а
не в `operations.external_id`: там всего 25 символов по проверке контроллера, и
GUID туда не влезает.

## Сторно и отрицательные суммы

1С пишет сторно отрицательной суммой по той же стороне. Мы это сохраняем как
есть: у FINDIR такая же модель — сторно уменьшает оборот своей стороны, а не
создаёт оборот противоположной.

## Проверка файла

```
php artisan 1c:inspect-postings путь/к/файлу.json
```

Разбирает файл, проверяет по этому описанию и печатает сводку: период,
организацию, число проводок, сумму и — главное — **список встреченных счетов 1С**.
Он же нужен, чтобы заполнить таблицу соответствия счетов перед загрузкой.
