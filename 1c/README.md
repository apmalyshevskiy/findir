# Выгрузка проводок из 1С в FINDIR

Внешняя обработка для 1С:Бухгалтерии 3.0. Выгружает проводки за период в файл
JSON, который потом загружается в FINDIR.

**Этот файл — про сборку и устройство.** Как этим пользоваться в работе —
выгрузить месяц, сопоставить счета, загрузить — написано в
[ИНСТРУКЦИИ](ИНСТРУКЦИЯ.md). Читатели разные: здесь программист с
Конфигуратором, там бухгалтер и финансовый директор.

Формат файла описан в [FORMAT.md](FORMAT.md), пример — в [sample.json](sample.json).

## Что здесь лежит

| Файл | Что это |
|---|---|
| `ИНСТРУКЦИЯ.md` | Как выгружать из 1С и загружать в FINDIR — для работы |
| `ВыгрузкаПроводок.bsl` | Модуль объекта: запрос к регистру, сбор структуры, запись JSON |
| `ВыгрузкаПроводокФорма.bsl` | Модуль формы: период, организация, кнопка, выбор файла |
| `FORMAT.md` | Спецификация формата обмена |
| `sample.json` | Эталонный файл для проверки приёмника |

**Здесь нет готового `.epf`** — это не упущение. Файл обработки собирается
Конфигуратором 1С из исходников, а 1С в среде разработки FINDIR нет. Собрать
нужно один раз, дальше обработка просто лежит в базе.

## Сборка в Конфигураторе

1. **Конфигуратор → Файл → Новый → Внешняя обработка.**
2. Имя: `ВыгрузкаПроводокВFindir`, синоним: `Выгрузка проводок в FINDIR`.
3. **Реквизиты обработки** — не нужны, всё живёт на форме.
4. **Модуль объекта**: открыть и вставить целиком содержимое
   `ВыгрузкаПроводок.bsl`.
5. **Формы → добавить форму**, вид «Форма обработки», имя `Форма`, отметить
   «Основная форма обработки».
6. На форме создать **реквизиты**:

   | Имя | Тип |
   |---|---|
   | `ДатаНачала` | Дата, состав — Дата |
   | `ДатаОкончания` | Дата, состав — Дата |
   | `Организация` | СправочникСсылка.Организации |
   | `ПутьКФайлу` | Строка, неограниченная |

7. Перетащить все четыре реквизита на форму. У поля `ПутьКФайлу` включить
   свойство **«Кнопка выбора»** — иначе выбор файла не откроется.
8. Создать **команду формы** `Выгрузить`, заголовок «Выгрузить», и вынести её
   кнопкой на командную панель формы.
9. **Модуль формы**: вставить целиком содержимое `ВыгрузкаПроводокФорма.bsl`.
10. У поля `ПутьКФайлу` в свойствах, событие **НачалоВыбора**, выбрать
    обработчик `ПутьКФайлуНачалоВыбора`.
11. Сохранить как `ВыгрузкаПроводокВFindir.epf`.

## Подключение в базе

Обработку можно просто открывать через **Файл → Открыть** — этого достаточно
для разовой выгрузки.

Чтобы она была под рукой у бухгалтера:
**Администрирование → Печатные формы, отчёты и обработки → Дополнительные
отчёты и обработки → Создать → выбрать файл `.epf`**. Функция
`СведенияОВнешнейОбработке()` в модуле объекта уже написана — без неё 1С
отказалась бы регистрировать обработку.

Право «Открытие внешних обработок» у пользователя должно быть включено.

## Как пользоваться

Порядок работы — период, организация, кнопка, потом загрузка в FINDIR — описан
в [ИНСТРУКЦИИ](ИНСТРУКЦИЯ.md). Здесь только то, что нужно администратору.

Проверить файл, не открывая FINDIR:

```
php artisan 1c:inspect-postings путь/к/файлу.json
```

Команда скажет, соответствует ли файл формату, и покажет период, число проводок,
контрольную сумму и **список встреченных счетов 1С**. Ненулевой код возврата,
если в файле есть испорченные проводки, — годится для проверки в скрипте.

## Что выгружается

Движения регистра бухгалтерии `Хозрасчетный` за период, с отбором по
организации и `Активность = Истина`.

Запрос идёт к виртуальной таблице
`РегистрБухгалтерии.Хозрасчетный.ДвиженияССубконто(&ДатаНачала, &ДатаОкончания)`,
а не к самому регистру. Это не стилистика: у главной таблицы регистра
бухгалтерии субконто нет как колонок — они хранятся отдельно, и запрос к
`Хозрасчетный.СубконтоДт1` падает с «Поле не найдено». Период задаётся
параметрами виртуальной таблицы, обе границы включаются.

Из каждой строки движения берётся: дата, счёт дебета и кредита по коду,
субконто обеих сторон (вид, представление, код, ИНН у контрагентов), сумма,
количество по сторонам, содержание, документ-регистратор и его GUID.

**Проводки без суммы и без количества пропускаются.** Такие движения бывают у
служебных документов: учёту в FINDIR они ничего не дают, а строк добавляют.

**Сторно выгружается отрицательной суммой**, как его и хранит 1С. У FINDIR та
же модель: сторно уменьшает оборот своей стороны, а не создаёт оборот
противоположной.

## Если при сборке ругается

**«Переменная не определена (ДатаНачала)»** и то же про `ДатаОкончания`,
`Организация`, `ПутьКФайлу` — не созданы реквизиты **формы** (шаг 6). Обратите
внимание: именно формы, а не обработки. Если создать их как реквизиты обработки,
код в модуле формы должен был бы обращаться к ним как `Объект.ДатаНачала`, и
проверка выдаст ровно эту ошибку.

Подсказка по номерам строк: ругается только там, где переменная **читается**
(строки 32, 37, 42, 96, …). Присваивания (`ДатаНачала = НачалоМесяца(…)`) молчат,
потому что 1С считает их созданием локальной переменной. Так что «ошибок мало»
не значит «половина реквизитов на месте».

**«Поле не найдено "Хозрасчетный.СубконтоДт1"»** — исправлено в текущей версии
модуля: запрос идёт к `ДвиженияССубконто`, см. «Что выгружается». Если ошибка
всё же появилась, значит в Конфигуратор попала старая версия
`ВыгрузкаПроводок.bsl` — перевставьте модуль объекта.

**«Значение содержит данные недопустимых типов» на `ЗаписатьJSON`** — в структуру
выгрузки попало значение, которое сериализатор писать не умеет. Само сообщение
платформы бесполезно: ни поля, ни типа, ни номера проводки в нём нет.

Ключевое, из-за чего это ловилось трижды: **`ЗаписатьJSON` не принимает ни
`Неопределено`, ни `Null`**. Обозначить пустоту значением нечем — пустое поле в
структуру просто не кладётся, для этого есть `ВставитьЕслиЕсть`. В файле такое
поле выглядит как отсутствующий ключ, и приёмник читает его как пустое.

Перед записью работает `ПроверитьПередЗаписью`: она обходит выгрузку и называет
путь к первому негодному значению, например
`выгрузка.entries[0].debit.quantity — Неопределено`. По такому сообщению сразу
видно, куда смотреть.

Правила при правке модуля: пустое поле не заполняем, а не кладём; всё, что
пришло из метаданных или из реквизита, оборачиваем в `Строка()`.

## Про кодировку

Файл пишется в UTF-8 **без BOM**. В обоих местах, где это решается, стоит явный
`Ложь`: в `ОткрытьФайл(..., "UTF-8", Ложь, ...)` и в
`ПолучитьДвоичныеДанныеИзСтроки(..., "UTF-8", Ложь)`.

Это не придирка. `ЗаписьТекста` в UTF-8 ставит BOM по умолчанию, BOM попадает в
начало файла, и на приёмнике `json_decode` возвращает пустоту без объяснения
причины. Приёмник BOM всё же срезает — но полагаться на это не надо.

## Чего эта обработка не делает

Не отправляет файл в FINDIR по сети и не ходит в интернет. Только формирует
файл на диске — его загружает человек. Обмен по сети, если понадобится, будет
отдельной работой: понадобится адрес, токен и разрешение на исходящие
соединения с сервера 1С.
